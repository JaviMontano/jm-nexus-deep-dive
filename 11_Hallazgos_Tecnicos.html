Graceful Degradation

src/agents/fallback-chain.ts

Cascada Groq → OpenRouter → Gemini. Si un proveedor falla, el siguiente absorbe. Degrada calidad pero mantiene disponibilidad.

Prompts ensamblados por capas: system base + constitution excerpt + agent persona + context window. Modular y testeable.

04 Hallazgos de Seguridad
✓
CP1 / CP2 — HARD blocks. Sólidos. Bloqueo efectivo de contenido prohibido y límites de tamaño/frecuencia.
!
CP3 — SOFT pass. HIGH — Mischaracteriza su propio rol: se describe como filtro final pero opera como scan informativo. Research injection podría pasar sin bloqueo.
~
IAM. Constitution exige isolation de agentes, pero no existen tests de enforcement que verifiquen que un agente no pueda escalar privilegios.
✓
Secrets. Firebase Secret Manager utilizado correctamente para API keys de proveedores LLM.
~
Prompt Injection. CP3 realiza soft scan. Research sandbox para ejecución aislada no confirmado en el código.
05 Hallazgos de Performance
✓
ACK <2 s vía Pub/Sub. Correctamente desacoplado. El usuario recibe confirmación de recepción instantánea.
✓
Budgets de tiempo. Single 15 s, Terna 30 s, Committee 60 s. Razonables para las modalidades de operación declaradas.
~
KB >100 MB split. Riesgo de cold start en Cloud Functions al cargar knowledge bases grandes. Sin lazy loading confirmado.
~
Token tracking básico. Archivos tokens.ts y quota-notifications.ts existen, pero no hay presupuesto por request ni alertas granulares de FinOps.
06 Hallazgos de Data Model
✓

✗
Sin Project State ni pending_actions. Capacidad crítica ausente — no hay forma de rastrear estado de proyectos multi-sesión.
!
Sin CRON de compresión confirmado. La memoria a largo plazo podría crecer sin límite.
!
Sin TTL enforcement visible. No se encontraron reglas de expiración automática en documentos Firestore.
~
Audit log no visible. No se identificó una colección dedicada para trazabilidad de operaciones.
